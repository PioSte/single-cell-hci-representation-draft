# Architectural review — `fuse-channels`

Date: 2026-10-23 00:43
Scope: architecture, naming, prose-vs-code, and reference support for
`src/fuse_channels/`, `README.md`, `docs/handoff.md`, tests, examples, viz.
Method: five parallel read-only scouts (prose consistency, identity/PMA
references, MAE references, standardness, naming/API), plus direct verification
of the highest-impact claims. All paper evidence comes from the existing
MinerU extracts in `references/*/paper.md`; no new papers were needed.

Severity: **Critical** = wrong math / missing core training signal;
**High** = architecture or prose materially wrong; **Medium** = non-standard
design, performance, or API problem; **Low** = cleanup/naming.

---

## 0. Executive summary

The core front-end is well matched to its references: tied `Conv2d(1→D)` patch
embedding, additive learned per-marker identity, shared spatial position, and
per-location single-query channel attention are genuinely Panopticon-style
(`panopticon/paper.md:92`) and the padding-free segmented implementation is
correct. The MAE half is where the implementation departs from both the handoff
and ChA-MAEViT.

Top issues, in order:

1. **The encoder is not a standard transformer block.** `TransformerBlock` has
   no Q/K/V projections and no output projection; attention is parameter-free
   over the raw normalized features, followed by an MLP. Verified parameter
   list: `norm1`, `norm2`, `mlp` only. The decoder and fusion/pooling modules
   also omit Q/K/V (the decoder has only `attn_out`).
2. **The advertised inference descriptor is never trained.** `pooler` appears
   only in `encode()`, which is `@torch.no_grad`; after a MAE backward all
   pooler gradients are `None`.
3. **`p_patch=p_channel=0` silently disables masking**, while in ChA-MAEViT
   that is the *combined* DCP configuration and their best result. The third
   (patch OR channel) branch is absent.
4. **The handoff's "unmasked channel tokens" wording is incompatible with a
   decoder that must use only the encoder's final representation.** The code is
   correct to feed the encoder's fused output; the missing piece is target
   self-attention among masked channel-patch queries, not raw channel tokens.
5. **Several README claims are factually wrong** (flash-attn path,
   `[ΣC,D]` flattening, ChannelViT "padded"/"C×C", Table 11 interpretation,
   "encoder sees only visible tokens", "implements the handoff" despite missing
   HCS and probes).
6. **Tests do not cover the acceptance criteria they are cited for**
   (`test_omission_equivalence`, `test_padding_free_encoder_input`,
   `test_no_pad_artifacts`, memory ablation, identity degradation).

## 1. Architecture and correctness

### A1. Attention modules have no Q/K/V projections; encoder has no W_O — **Critical**

Evidence:
- `src/fuse_channels/encoder.py:17-35`: `TransformerBlock.forward` calls
  `grouped_self_attention(self.norm1(x), ...)` and adds the result. No
  `q_proj/k_proj/v_proj`, no `out_proj`.
- `src/fuse_channels/ops.py:27-71`: `grouped_self_attention` reshapes `x`
  directly into heads and calls `F.scaled_dot_product_attention(x, x, x)`.
- `src/fuse_channels/decoder.py:31,41-44`: cross-attention has `attn_out` but
  still uses `norm_q(q)` / `norm_kv(kv)` directly; no Q/K/V projections.
- `src/fuse_channels/fusion.py:76-80,171-174`: the pooling modules have a
  learned query and an output projection, but no `W_K`/`W_V`.

Direct verification: `encoder.blocks[0].named_parameters()` =
`norm1.weight`, `norm1.bias`, `norm2.weight`, `norm2.bias`, `mlp.0.weight`,
`mlp.0.bias`, `mlp.3.weight`, `mlp.3.bias`.

Why it might exist: the fusion module was written to match Panopticon's
single-query channel attention, and the author simplified away projections
there. The encoder appears to have inherited the same primitive. The viz README
even documents "no W_Q/W_K/W_V" for fusion (`viz/README.md`, fusion_flow
section), but nothing documents it for the encoder.

Why it is a problem: a multi-head transformer block without Q/K/V projections
does not learn per-head subspaces; heads are fixed slices of the same feature
vector. Without W_O, the encoder cannot mix heads at all. This is not a
"simpler transformer"; it is a different, much weaker model. It also makes the
class name `SpatialTransformer` misleading.

Recommendation:
- Add `q_proj`, `k_proj`, `v_proj`, `out_proj` to `TransformerBlock` (standard
  pre-norm transformer block).
- Add Q/K/V projections to `DecoderBlock` (`out_proj` already exists).
- For `ChannelFusion`/`MultiheadAttentionPooling`, either add `k_proj`/`v_proj`
  (and optionally `q_proj`) or explicitly document the projection-free
  simplification and benchmark it. Panopticon and Set Transformer both use
  standard MHA (`panopticon:92`, `set-transformer:159-163`).

Reference: Set Transformer MAB = MHA with projections plus rFF
(`set-transformer/paper.md:157-163`); ChannelViT/ChA-MAEViT use standard ViT
blocks (`channelvit/paper.md:99-105`, `cha-maevit/paper.md:129`).

### A2. The inference descriptor pooler is untrained — **Critical**

Evidence:
- `src/fuse_channels/mae.py:71`: `self.pooler = MultiheadAttentionPooling(...)`.
- `src/fuse_channels/mae.py:154-202`: `pooler` is used only in `encode()`,
  which is decorated `@torch.no_grad()`.
- Direct check after `out["loss"].backward()`: all pooler parameters have
  `grad is None`.

Why it might exist: the descriptor was treated as an inference-time readout,
and the MAE training path never needs `[B,D]`.

Why it is a problem: the README advertises the attention-pooled descriptor as
the model's fixed-size representation (`README.md:45-47,143-145`), but its
query, norms, and projection are random at initialization and never updated.
A downstream linear probe cannot fix this because `encode()` is no_grad. The
"PMA descriptor" is therefore a random attention pool over trained tokens.

Recommendation (choose one):
- Add the descriptor to the training objective (auxiliary head / contrastive or
  reconstruction term), and remove `@torch.no_grad` for the trainable path.
- Or drop the learned pooler and make `pool="mean"` (or a CLS token) the
  documented default.
- At minimum, do not present the pooler as a trained representation.

Reference: PMA is a learned pooling operation (`set-transformer:157-171`); a
readout that is never optimized is not PMA in any useful sense.

### A3. DCP masking semantics are wrong for the paper's best configuration — **Critical**

Evidence:
- `src/fuse_channels/masking.py:56-76`: mode is selected only by
  `rand < p_channel`; otherwise `visible = r >= p_patch`.
- With `p_patch=p_channel=0`: `channel_mode=False`, `r >= 0` is always true, so
  **no token is masked**. Verified: visible fraction = 1.0.
- ChA-MAEViT Eq. 1 has three regions: patch, channel, and `patch OR channel`;
  `p_patch=p_channel=0` selects the combined branch, their best DCP variant
  (`cha-maevit/paper.md:97-107,252-255`).
- The docstring `masking.py:11` says "one of the two modes is chosen
  (`p_patch` / `p_channel`)", but `p_patch` is the spatial mask ratio, not a
  mode probability (`masking.py:76`).
- The paper samples a fixed count `floor(n*r_p)` patches per channel; the repo
  uses independent Bernoulli draws (`masking.py:75-76`).
- The paper switches mode per training iteration; the repo switches per sample
  (`masking.py:59-61`).

Why it might exist: a two-mode implementation is simpler, and per-sample
switching gives more mask diversity.

Why it is a problem: the paper's recommended configuration silently degenerates
to no masking; the public knobs do not mean what the paper means; and
channel-masked vs spatial-only comparisons are not reproducible.

Recommendation:
- Implement Eq. 1 (three regions), or explicitly reject/validate
  `p_patch + p_channel < 1` and document that only the Alternate variant is
  supported.
- Separate the patch mask ratio (`r_p`) from the mode probabilities.
- Sample exactly `floor(N*r_p)` patches per channel with `randperm` if
  reproducing ChA-MAEViT.
- Decide whether mode selection is per iteration or per sample and document it.

### A4. Decoder cannot see per-channel visible tokens; no target self-attention — **High**

Evidence:
- `src/fuse_channels/mae.py:93-104,133-134`: the encoder receives only
  `fused[present]`; the decoder receives `enc_all` = memory + fused tokens.
- `src/fuse_channels/decoder.py:41-45`: each target query cross-attends to
  `enc_all`; there is no self-attention among target queries.
- `docs/handoff.md:146-148`: the decoder was specified to be "fed the unmasked
  channel tokens + memory tokens".
- ChA-MAEViT's decoder runs transformer blocks over the token sequence
  `[CLS, memory, visible + channel-token, mask + channel-token]`
  (`cha-maevit/paper.md:119-129`).

Why it might exist: fusing before the encoder is the handoff's compute-bound
choice, and a Perceiver-IO-style cross-attention decoder is a valid way to
decode independent outputs (`perceiver-io:101`).

Why it is a problem: at a target patch, the decoder sees a channel *mixture*,
not the specific visible channels; it also cannot coordinate the predictions of
correlated masked channel-patches. This is exactly the information
ChA-MAEViT's channel-aware decoder preserves.

Decision (user): the decoder must consume only the encoder's final
representation, so it must not receive raw per-channel tokens. Keep the fused
encoder KV (`mem_out + tok_out`) and add grouped self-attention over target
queries only. Correct the handoff wording ("unmasked channel tokens" ->
"encoder representation + memory"). If channel-aware decoding is later
required, the encoder would have to preserve a channel axis; that is a
separate, larger architecture change, not a decoder tweak.

### A5. Channel identity is closed and exact-match only — **Medium** (documented limitation)

Evidence: `src/fuse_channels/identity.py:15-28`; `README.md:60-71`.
The table is `nn.Embedding(num_markers, dim)`; unseen ids raise. The README
acknowledges this, and the handoff specifies a closed panel. This is a
defensible design, but it sits in tension with the stated cross-lab panel
heterogeneity (`README.md:13-14`).

Recommendation: keep the table, but state the contract explicitly as
"fixed marker vocabulary; unknown ids are not representable" and offer an
optional UNK/hash row or an embedding-free fallback. No change needed if the
closed-panel scope is intentional.

### A6. `HypernetworkWeightedSum` runs its MLP per token, not per channel — **Medium**

Evidence:
- `src/fuse_channels/fusion.py:236-247`: `w_in = cs.identity` is `[T,D]`
  (T = C·N) and `weight_net(w_in)` is evaluated for every token. The identity
  is constant across the N patches of a channel, so the same logits are
  recomputed N times.
- The module is advertised as the cheap `O(C)` alternative
  (`fusion.py:8,208-211`); the real MLP cost is `O(C·N·D·hidden)`, i.e. N times
  the intended cost.

Why it might exist: `ChannelSet` stores identity per token, so the simplest
implementation reuses that tensor.

Why it is a problem: at C=60, N=16 (the benchmark), this is 16× redundant work;
at N=196 it is ~196×. It weakens the exact regime the module exists for.

Recommendation: compute logits once per `(sample, channel)` and broadcast to
patches; or store per-channel identity in `ChannelSet`. Then the benchmark
honestly measures the `O(C)` claim.

Additional issue: `fusion.py:236-239` silently falls back to token features
when `identity is None`, changing marker routing into content routing. Raise an
error or document the fallback.

### A7. `HypernetworkWeightedSum` is not a hypernetwork — **Medium (naming)**

Evidence: `src/fuse_channels/fusion.py:207-262`; `README.md:42,195`.
It emits per-channel softmax logits. DOFA/HyperFree hypernetworks generate
*network weights* (convolution kernels / a weight dictionary)
(`dofa/paper.md:133,175-197`; `hyperfree/paper.md:101-105`).

Recommendation: rename to `IdentityGatedSum` / `MarkerGatedSum` /
`AttentionWeightedSum`, or add a README sentence: "called hypernetwork for
historical reasons; it is a small MLP that emits per-channel mixing weights,
not a weight-generating hypernetwork."

### A8. No explicit positional embedding after fusion — **Medium**

Evidence:
- `src/fuse_channels/patch_embed.py:31-32,66`: `spatial_pos` is added to each
  channel patch before channel fusion.
- `src/fuse_channels/mae.py:97-98`: the encoder receives `fused[present]` with
  only sample segment ids; no patch index or PE is passed.
- `src/fuse_channels/encoder.py:59-79`: the spatial transformer has no PE.
- Panopticon applies channel reduction first and then adds spectral/positional
  embeddings (`panopticon:92-108`); ViT/ChannelViT add PE to transformer tokens
  (`channelvit:99-103`).

Why it might exist: the pre-fusion `spatial_pos` is assumed to survive the
attention/projection, avoiding a second PE parameter.

Why it is a problem: after per-token LayerNorm and the attention softmax,
position is only implicit in K/V values, not a clean additive signal; fully
masked locations are dropped without a positional gap marker. Spatial
self-attention is otherwise permutation-equivariant.

Recommendation: add `spatial_pos` (or a patch-id-derived PE) to `fused` before
the encoder, and remove or repurpose the pre-fusion PE to avoid double-counting.
Alternatively, document that position is carried only through the pre-fusion
embedding and evaluate that choice.

### A9. Masker repair reveals whole channels; zero-target samples — **Medium**

Evidence: `src/fuse_channels/masking.py:78-90`.
If fewer than `min_visible_channels` channels have any visible patch, the guard
sets entire rows `visible[c] = True`, un-masking a whole channel. In channel
mode, `k=0` is possible, and for C=1 the guard un-masks the only channel, so
channel-mode samples produce no targets. `mae.py:122-124` then returns a zero
loss if no sample has targets.

Why it might exist: it enforces the "never mask all channels" handoff rule with
minimal logic.

Why it is a problem: it can leak a whole channel in spatial mode, and it wastes
training samples with zero targets. Loss is token-weighted, so samples with few
targets are underweighted.

Recommendation: resample the mask (or force one visible patch per channel)
instead of revealing a whole row; guarantee at least one target per sample or
return a per-sample validity mask and normalize per sample.

### A10. Descriptor modes are inconsistent; `pool="memory"` NaNs with `n_memory=0` — **Medium**

Evidence:
- `src/fuse_channels/mae.py:185-202`: `attention` pools `[memory; visible]`,
  `mean` pools visible tokens only, `memory` averages memory tokens.
- With `n_memory=0`, `pool="memory"` computes a mean over an empty axis.
  Verified: output is all `NaN`.
- `README.md:143-145` calls `mean` "the old mean pool" although it is a current
  first-class option; `memory` is undocumented.

Recommendation: define one canonical readout; guard `n_memory=0` in
`pool="memory"`; mark `mean` as an ablation; remove or document `memory`.

### A11. Loss deviates from the cited ChA-MAEViT objective — **Medium (prose/method)**

Evidence: `src/fuse_channels/losses.py:3-5,19-31`; ChA-MAEViT uses
`(1-λf)·L_pixel + λf·L_fourier` on masked patches, with `λf=0.01`
(`cha-maevit:137-143`). The repo implements per-patch z-normalized MSE and no
Fourier term.

Why it might exist: per-patch normalization is the standard MAE objective
(He et al.), and the Fourier term is optional.

Why it is a problem: the docstring mentions the paper's L2+Fourier loss, but
the code implements neither; readers may believe ChA-MAEViT was reproduced.

Recommendation: state explicitly "this repo uses the standard MAE
patch-normalized MSE; it does not implement ChA-MAEViT's Fourier L1 term."
Optionally add the Fourier term behind a flag.

### A12. `n_queries > 1` is advertised but not a real multi-query bottleneck — **Low/Medium**

Evidence: `src/fuse_channels/mae.py:65-66`; `fusion.py:103-109`.
Multiple queries are flattened to `Q*D` and linearly projected to `D`; there is
no interaction among query slots (no SAB). Tests use `n_queries=1` only.

Recommendation: restrict to `n_queries=1`, or add self-attention over the query
outputs before `fuse_proj` (Set Transformer PMA + SAB,
`set-transformer:159-171`), and test it.

### A13. Attention dropout is dead — **Medium (implementation)**

Evidence: `encoder.py:31` passes `dropout_p=0.0`; `decoder.py:41-44` never
passes `dropout_p` to `grouped_cross_attention`; `ChannelFusionMAE` does not
expose a `dropout` argument. Only MLP/residual dropout can be enabled.

Recommendation: thread `dropout_p` through all attention calls and expose a
model-level `dropout` argument, or remove the unused parameter.

## 2. Reference-support corrections

These are places where the code/prose claims support that the cited paper does
not provide.

### B1. ChannelViT Table 11 is not a one-hot-token ablation — **High (prose)**

`README.md:95-101` uses Table 11 as evidence against one-hot *token* identity.
Table 11 conditions the **final classifier** on the channel combination; the
backbone in every row is the same ChannelViT with additive per-token `chn`
(`channelvit/paper.md:692-714`). The numbers (66.86 / 61.98 / 68.09) are
correct, but the inference is not. The paper's own conclusion is about the
shared classifier regularizing the embedding space (`:714`).

Recommendation: cite Table 10 (mean-embedding ablation, `:670-688`) for
"identity matters"; cite Table 11 only for "classifier conditioning does not
beat a shared classifier"; do not use it as a direct one-hot-token ablation.

### B2. README's one-hot argument is internally contradictory — **High (prose)**

`README.md:76-84` correctly shows
`concat(x, onehot(m)) @ W = W_x x + E[m]`, i.e. the one-hot path is a learned
embedding row. `README.md:102-113` then argues that one-hot codes are
orthogonal while learned embeddings carry similarity. That argument applies
only to a *fixed* one-hot without a learned projection; the concat path learns
`W_e` and can encode any similarity. The real advantages of the table are
parameter count, width, and the shared-classifier regularization — not
expressiveness.

Recommendation: rewrite the section as "the table is the parameter-efficient
parameterization of the same additive bias; the width/optimization argument is
the reason to prefer it." Drop or qualify points 3-4.

### B3. "Every reference architecture uses additive learned embedding" is false — **Medium**

Panopticon's optical identity is a *fixed* sinusoidal encoding of wavelength,
and its SAR embeddings are concatenated (`panopticon/paper.md:94-108`).
DOFA/HyperFree use hypernetwork-generated weights, not additive token
embeddings. The claim should be narrowed to the ChannelViT / ChAda-ViT /
ChA-MAEViT family.

### B4. "Dense padded" and "O(C²) C×C" mischaracterize the baselines — **Medium**

ChannelViT concatenates `C·N` tokens into one ViT sequence and uses HCS to
shorten it; it does not pad (`channelvit/paper.md:37-41,107-117`). ChAda-ViT
does pad/mask (`chada-vit:121-129`). Both attend over `C·N` (or padded
`C_max·m`) tokens, giving `O((C·N)²)`, not a per-location `C×C` block.
Panopticon also uses padding+masking in its implementation
(`panopticon:581`).

Recommendation: say "avoids full joint self-attention over the C·N
channel-patch sequence; fusion costs O(C) per location." Keep "padded" only for
ChAda-ViT.

### B5. Perceiver identity citation is about position, not identity — **Low/Medium**

`README.md:110-113` cites `perceiver:120,132` for "identity should be a
feature the net can use or ignore." Those lines are in the position-encoding
section; `perceiver:130` even says Perceiver concatenates position rather than
adds it. Perceiver-IO's modality/task embeddings (`perceiver-io:101-103`) are
the right citation for identity.

### B6. ChA-MAEViT line citation is off — **Low**

`README.md:87-90` cites `cha-maevit:113` for "channel tokens added to patch
tokens"; line 113 is the memory-token formula. The additive channel-token
statement is at `:121-125`.

### B7. "Data-dependent weighting" is only true for the attention variant — **Medium**

`README.md:18-20` states aggregation weights are data-dependent.
`ChannelFusion` weights depend on token content; `HypernetworkWeightedSum`
weights depend only on marker id (`fusion.py:236-240`), so for a fixed panel
they are identical across samples and locations. Qualify the README or rename
the hypernetwork variant.

### B8. Decoder conditioning source differs from ChA-MAEViT — **Medium**

ChA-MAEViT conditions on encoder-optimized channel tokens added to patch
tokens (`cha-maevit:121-125`); the repo conditions on the raw identity table
projected by `target_proj` (`decoder.py:91-94`, `mae.py:128-131`). The query
construction is standard Perceiver-IO practice (`perceiver-io:101-103`), but it
is not the paper's mechanism. Document the substitution.

## 3. Naming and API

### C1. `grouped_*_attention` collides with grouped-query attention — **Medium**

`ops.py:27,74,119` implement segmented/varlen attention, not GQA.
Recommendation: rename `segmented_*_attention` or `varlen_*_attention`;
keep `segment_softmax`.

### C2. Identity vocabulary is incoherent — **Medium**

Current names: `ChannelIdentity` (module), `identity` (field), `channel_id`
(marker id), `num_markers` (model), `n_markers` (dataset). `channel_id` is not
a channel position and is never read in `src/`. Recommendation:
- `ChannelIdentity` → `ChannelEmbedding`
- `ChannelSet.identity` → `channel_embed`
- `ChannelSet.channel_id` → `marker_id` (or remove until used)
- unify `num_markers` / `n_markers`
Add one README sentence: "marker id = biological target; channel index =
position in the sample's panel."

### C3. `HypernetworkWeightedSum` — **Medium**

See A7. Rename or explain.

### C4. `DCPMasker` returns visibility, not a mask — **Low/Medium**

`masking.py:23,99` returns a *visible* boolean mask; the paper's `mask` marks
masked patches. `visible_to_masked` exists only to invert it and is unused
outside its own test. Recommendation: rename `DCPVisibilitySampler`, or return
the masked mask and invert internally; remove `visible_to_masked`.

### C5. `ChannelFrontend` boundary is ambiguous — **Low**

`patch_embed.py:105` covers only patch embed + identity, while README calls the
whole pipeline a "channel-fusion front-end" (`README.md:3`). Recommendation:
rename `ChannelTokenizer`, or add a README sentence defining the three stages
(frontend / fusion / encoder).

### C6. "PMA" is used for a single-layer attention pool — **Low/Medium**

`ChannelFusion` and `MultiheadAttentionPooling` are one MHA + linear, without
Set Transformer's MAB rFF or post-SAB (`set-transformer:157-171`).
`ChannelFusion` is genuinely Panopticon's per-location single-query attention
(`panopticon:92`), so the mechanism is fine; the label "canonical PMA" is not.
Recommendation: say "PMA-style / single-layer attention pool" and either add
the MAB feed-forward or stop calling it canonical PMA.

### C7. Output-term soup — **Low**

"fused", "joint embedding", "descriptor", "pooled", "memory" all appear.
Recommendation: `fused` = per-location `[B,N,D]`; `pooled`/`descriptor` =
per-sample `[B,D]`; reserve "joint embedding" for the `encode()` output.

### C8. Dead/test-only API — **Low**

- `dense_fusion_reference` is exported (`__init__.py:10,29`) but test/viz-only
  (`fusion.py:266-267`). Make it private.
- `visible_to_masked` is exported and used only by its own test
  (`__init__.py:15,38`). Remove.
- `ChannelSet.seq_len` is stored and moved but never read
  (`container.py:36-48,64`). Remove.
- `ChannelSet.to` is never called (`container.py:51`). Keep as convenience or
  remove.
- `ChannelSet.channel_id` is never consumed in `src/`. Keep as metadata or
  remove.
- `n_patches` constructor args in `ChannelFusion`/`HypernetworkWeightedSum` are
  asserted but ignored in favour of `cs.n_patches` (`fusion.py:54-55,94,226`).
  Validate equality or derive.

### C9. `SpatialTransformer` name — **Low**

After A1 it should be `TransformerEncoder` or `MemoryAugmentedEncoder`.
Currently it overpromises a transformer and hides the memory tokens.

## 6. Proposed README additions for unusual names

If the names are kept, add a short "Terminology" subsection:

- **Front-end / fusion / encoder.** `ChannelFrontend` = tied patch embedding +
  additive marker embedding; `ChannelFusion` = per-location channel-axis
  attention; `SpatialTransformer` = the spatial encoder over fused locations.
- **Marker vs channel.** A *marker* is the biological target (the identity
  key); a *channel* is its position in a sample's panel. `marker_id` selects
  the embedding row; `channel_idx` is the panel position.
- **Descriptor / joint embedding.** `fused` is `[B,N,D]` (one token per spatial
  location); `descriptor`/`joint embedding` is the `[B,D]` pooled output of
  `encode()`.
- **PMA.** Used in the Set Transformer sense for a learned-query attention
  pool; `ChannelFusion` is a single-layer, projection-free variant of
  Panopticon's per-patch single-query channel attention.
- **DCP.** Dynamic Channel-Patch masking from ChA-MAEViT. This repo implements
  only the Alternate two-way variant; it returns a *visibility* mask.
- **HypernetworkWeightedSum.** A small MLP emits per-marker softmax mixing
  weights; it does not generate network weights. Rename or state the
  historical usage.

## 7. Decision log (resolved 2026-10-23)

These are the user's decisions after the review Q&A; they supersede the
"choose one" recommendations in the finding sections.

1. **A1 attention projections.** Add standard Q/K/V and output projections to
   `TransformerBlock` and `DecoderBlock`. Keep `ChannelFusion` projection-free
   as the intentional Panopticon-style simplification, but document it and
   benchmark it. (`ChannelFusion` also gets the post-fusion PE; see A8.)
2. **A2 descriptor.** Train the `[B,D]` descriptor in the MAE. Compute it in
   `forward` from content tokens only (`tok_out`), append it as one extra
   per-sample token to the decoder KV, and add standard Q/K/V/O to the pooler
   (PMA-style, `k=1`). `pool="mean"` stays as a content-only ablation;
   `pool="memory"` is removed. Optional `k>1` ablation: multiple seeds, SAB
   over the `k` outputs, and a readout back to `[B,D]` (or expose `k` vectors).
3. **A3/A9 DCP.** Implement ChA-MAEViT Eq. 1 fully: patch, channel, and
   patch-OR-channel regions. Separate `p_patch`/`p_channel` mode probabilities
   from `patch_ratio=0.75`. Use fixed-count `randperm` sampling per channel and
   resample guards instead of revealing whole channels. Mode selection is
   per-batch by default (`s` drawn once per step, paper-faithful) with a
   `mode_sampling="sample"` flag.
4. **A4 decoder.** The decoder consumes only the encoder's final
   representation (`mem_out + tok_out`); it must not receive raw per-channel
   tokens. Add grouped self-attention over the target queries per sample.
   Correct the handoff wording from "unmasked channel tokens" to "encoder
   representation + memory".
5. **A6/A7 gated-sum ablation.** Keep the variant as an explicit ablation, but
   compute its logits once per `(sample, channel)` and broadcast to patches;
   raise if `identity is None`; rename `HypernetworkWeightedSum` to
   `IdentityGatedSum` and update the `fusion` selector/README/benchmark.
6. **A8 position.** Move the spatial PE post-fusion: remove it from
   `ChannelTiedPatchEmbed`; add a learned spatial PE to the fused `[B,N,D]`
   tokens before the encoder (in the fusion modules or `MAE.forward`). The
   channel attention becomes position-agnostic, which is acceptable for
   per-location channel pooling.
7. **A10/A11 loss and readout modes.** Standard MAE `normalized_patch_mse` is
   the default. Add the ChA-MAEViT reconstruction loss (raw-pixel L2 + Fourier
   L1, `lambda_f=0.01`) as an ablation/selector. Keep `pool="mean"` as an
   ablation; remove `pool="memory"`.
8. **A12/A13 minor.** `ChannelFusion` is restricted to `n_queries=1` (remove
   the flatten+`fuse_proj` path); multi-query research lives in the descriptor
   pooler. Thread `dropout_p` through encoder/decoder attention and expose a
   model-level `dropout`.
9. **B1/B2 identity rationale.** Rewrite around parameter/width efficiency and
   the shared-classifier regularization. Cite ChannelViT Table 10 for "identity
   matters"; use Table 11 only for classifier conditioning. Drop the claim that
   one-hot cannot express similarity (concat+linear learns an equivalent row).
10. **B3-B6 citations.** Correct all: Panopticon is fixed sinusoidal +
    concatenated SAR, not additive learned; ChannelViT does not pad; use "full
    joint attention over C·N" instead of "C·C"; Perceiver identity points to
    Perceiver-IO modality embeddings; ChA-MAEViT additive channel tokens are at
    `:121-125`, not `:113`. Fix all line references and wording.
11. **B8 decoder identity.** Keep the shared `ChannelEmbedding` table for the
    target query and document the two roles (input identity vs target
    specification). A fully masked channel has no encoder evidence, only its
    identity query.
12. **C naming.** Keep `channel_id` and `grouped_*`. Rename `seg` ->
    `group_id`, `n_segments` -> `n_groups`, `location_segments` ->
    `location_group_ids`, `segment_softmax` -> `grouped_softmax`.

    `num_channel_ids`/`n_channel_ids`; `ChannelFrontend` -> `ChannelTokenizer`;

    `dense_fusion_reference` private or test-only. Keep `channel_id`,
    `channel_embed`, and the `IdentityGatedSum` ablation. Remove the

14. **D README.** Correct every false/misleading claim (flash-attn,

15. **E handoff/tests.** Implement a per-step HCS sampler (sample
